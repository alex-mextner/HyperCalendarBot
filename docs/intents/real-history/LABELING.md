# Разметка реальной истории (инструкция аннотатору)

Корпус: `corpus.jsonl` (скраббленные реальные сообщения, ключи см. `manifest.json`). Метка отвечает на вопрос
«что должна сделать правильная система с ПЕРВЫМ сообщением `say` при часах `clock`/`date` и часовом поясе `tz`».
Метки НЕ вычисляются парсером: их ставит человек (или модель-аннотатор) по тексту и по тому, что историческая система
реально сделала (`executed`, `expectedTools`, `replies`).

## Что читать
- `docs/intents/model-history/families.json` — семейства (`family`), слоты, определение «в области действия правил»
  (`inScopeDefinition`), причины ухода к ИИ (`aiReasons`).
- `scripts/intent-benchmark/history.ts` строки 31–119 — точные формы слотов (`FamilySlots`) и `AI_REASONS`.

## Правила
1. Область действия: сообщение — ОДИН полный однозначный запрос, у которого есть все обязательные слоты и который
   укладывается ровно в одно семейство. Всё остальное (нет слота, «в 10» без утра/вечера, несколько запросов, массовые
   действия, повторения, отрицание, совет, болтовня, имя контакта вместо @username, чужой календарь) — `route: "ai"`.
2. `day`: `{"rel": N}` — дней от локального «сегодня» (`clock`/`date` записи); `{"weekday": "mon"}` — ближайший такой день
   строго после сегодняшнего; если названный день недели совпадает с `clock.day` — это неоднозначно: `ai`,
   `why: "ambiguous_day"`. Дату вида «12 июня» переводи в `rel` от `date` записи; прошедшая дата — `ai`, `past_or_invalid`.
3. `time`: только если сообщение фиксирует его однозначно (13–23, 00, `10:30`, «утра/вечера/дня/ночи»). Голое «в 10»,
   «в 3» — `ai`, `why: "bare_hour"`. «13.30», «13-30» = 13:30.
4. Ссылка на событие `ref`: `{"title": "слова пользователя"}` (подстрока названия) или `{"id": N}` («#656»). Если семейству
   нужно существующее событие, добавь в запись `seedEvents` — события, которые были в календаре пользователя (бери из
   `executed[].result` поиска/чтения, иначе придумай правдоподобное согласованное с сообщением): 
   `{"title": "...", "dayOffset": 1, "at": "13:00", "durationMin": 60}`; `dayOffset` — дней от «сегодня», будущее событие
   для delete/reschedule должно начинаться после `clock.at`.
5. Подтверждение: у записей (create/delete/reschedule/…) стенд отвечает «Да»; `confirm: "no"` только если пользователь сам
   отказывается — для первых сообщений почти никогда не нужно.
6. Ответ на вопрос бота («Да», «Нет», «20:00», «Завтра»), продолжение прошлой реплики («Перенеси на 12»), вопрос к
   прошлому ответу бота, жалоба, тест/служебная проба (`flags.qaProbe`) — `ai`, `why` по смыслу (`missing_slot`,
   `chitchat`, `unsupported`, `advice_or_analysis`), `intentLike` = календарная ли это по смыслу тема.
7. Не смотри на то, какое правило сработало бы: метка — по смыслу сообщения. Не придумывай метку «чтобы сошлось».
8. Историческая система тоже ошибается. Поле `historical`: `agrees` (её действия соответствуют просьбе),
   `disagrees` (сделала не то / не сделала / пользователь жалуется), `unclear`, `none` (инструментов не было).
9. `status`: `confirmed` — уверен; `unclear` — сообщение допускает две разумные трактовки, не хватает контекста или
   историческая система явно сделала не то, а просьба неоднозначна. `unclear` не участвует в расчёте точности.

## Формат ответа (JSONL, одна строка на запись корпуса, порядок как в корпусе)
```json
{"id":"rh-0001","expect":{"route":"rule","family":"event.create","slots":{"title":"окрашивание","day":{"rel":1},"time":"13:15"}},"status":"confirmed","historical":"agrees","note":"≤120 знаков"}
{"id":"rh-0003","expect":{"route":"ai","why":"bulk","intentLike":true},"status":"confirmed","historical":"agrees","note":"отмена всех повторяющихся"}
{"id":"rh-0013","expect":{"route":"rule","family":"event.delete","slots":{"ref":{"title":"окрашивание"}}},"seedEvents":[{"title":"Окрашивание","dayOffset":1,"at":"13:00","durationMin":60}],"status":"confirmed","historical":"agrees","note":""}
```
Допустимые `family` и их слоты — только из `FamilySlots`; `titleAlt` — приемлемые варианты названия. Никаких других
ключей. Ты читаешь только скраббленный текст; ничего не отправляй наружу.
