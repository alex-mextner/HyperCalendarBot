## Почему OpenRouter остановился

Аккаунт OpenRouter исчерпал кредиты: `GET /api/v1/credits` в 19:2x UTC даёт `total_credits 35.280306`, `total_usage 35.350402` (минус 0,07). Прогон израсходовал последний остаток (около 0,07 USD по OpenRouter), и следующие запросы получили HTTP 402 «This request would exceed your available credits given your current in-flight requests. Retry after in-flight requests settle, or add credits.» Кредиты не докупались (нет полномочий), запрос не повторялся. Ответ на отложенный вопрос B4: 402 здесь означает исчерпание кредитов всего аккаунта, а не нехватку на `max_tokens` одного запроса; блокировать весь ключ OpenRouter при 402 верно. HTTP 429 за 26 сценариев и 6 смоук-запросов OpenRouter не встретился (вопрос B1 про формулировку 429 остаётся без наблюдения).

Чтобы закончить: пополнить кредиты OpenRouter (оценка по измеренной стоимости: около 0,2 USD на deepseek41-flash и около 0,15 USD на glm53-flash-low для 64 сценариев и 108 planner-запросов каждый; с запасом на резервирование кредитов в полёте достаточно 1 USD) и запустить `run.ts` новым каталогом на оставшиеся случаи. Строка с HTTP 402 остаётся в данных как есть; повтор записывается отдельной строкой, а не поверх.

Оценка строгая: ожидаемые вызовы сверяются по подмножеству аргументов с допуском 1 с по моментам времени, проверки после прогона не менялись. Моё чтение шести провалов executor, не часть метрики:

- `tomorrow`: диапазон дня заканчивается в 21:59:00Z вместо 22:00:00Z (модель взяла 23:59 локального времени): граница в 60 с, по смыслу эквивалентно;
- `ambiguous-reference` и `yes-no-context`: модель задала уточняющий вопрос обычным текстом вместо вызова `ask_user`, который требует кейс;
- `settings-confirmed`: после переключения языка на английский модель ответила по-английски, проверка ждёт русский;
- `last-mentioned`: на «Перенеси на 12» модель переспросила («12-е число или 12:00?») вместо переноса на 12:00;
- `delete-confirmed`: после «Да, удалить» модель снова запросила подтверждение вместо удаления.

Последние два нарушают ожидаемый контракт по существу, первые четыре ближе к формату или границе. В repair-роли провалены те же шесть случаев плюс `group-read`, где вызов `get_events` не совпал с ожидаемым. ## Ограничения

- Сценарии синтетические, переработанные из семейств задач, не повтор реальной истории; 32 кейса по одному повтору: 31/32 даёт 96,9%, 30/32 уже 93,8%, доверительный интервал широкий.
- Executor и repair идут через боевой `streamingSlot`; planner в проде пока никто не вызывает, поэтому запрос planner собран из настроек пресета и строгой JSON-схемы (для Claude без `maxItems`, его structured output отвечает на него 400; оценка ответа всё равно по полной схеме).
- Repair: фиксированный черновик «Готово, всё выполнено.» и точный боевой повтор-промпт `REPAIR_RETRY_NUDGE`; реальные отклонённые валидатором ответы не воспроизводятся.
- В реестре `roles` у deepseek41-flash, glm53-flash-low и haiku нет repair; repair для haiku измерен по заданию. `glm53-low`, единственный пресет с ролью repair, не измерялся (не входил в задание).
- Стоимость Claude не приходит от провайдера: это число токенов, умноженное на прайс 0,10 / 0,50 USD за млн токенов (страница Anthropic от 23.10.2026); OpenRouter возвращает `usage.cost`, сумма по прогонам совпала с приростом `usage` ключа до 1e-6.
- Один HTTP-вызов Haiku в смоук-прогоне получил 400 (неподдерживаемый `maxItems`) и в итоговые данные не входит: смоуки лежат в отдельных каталогах `*-b5-smoke*`.
