## Метчинг — отдельные ступени, а не ещё один огромный regex

1. Точные алиасы: мультимапа, а не last-write-wins. Параметризованные примеры обязаны получить аргументы из исходного текста. Две разные цели — отказ от автоматического выбора.
2. Типизированные шаблоны: лексемы/слоты с исходными диапазонами, ограниченная грамматика, даты/время в IANA timezone и конкретном дне, числовые ID/ссылки. Сейчас исправляется только совместимый текущий matcher, не объявляется готовым полный typed-template engine.
3. Лексический и семантический поиск: извлекают небольшой набор кандидатов, но не разрешают запись. Сравнить exact, morphology/BM25, embeddings и NLI на одинаковом размеченном отложенном корпусе; цена ошибки и calibrated margin важнее общей доли совпадений. Пользовательская опечатка не должна автоматически удалить похожее событие.
4. Контекст и составные запросы: отдельный план обязательств, привязка event/user references к этому диалогу, проверка выполненных шагов. Light/Medium/Smart подключается к выбору/восстановлению; модель не заменяет проверку прав и idempotency.
5. Отрицания, цитаты, чужой текст, неоднозначность времени/имени и дополнительные действия — отдельные отрицательные тесты. Результат matcher — кандидат/аргументы/причина отказа, не сообщение «готово».

## Язык и движок

Bounded JSON-значения для входов, валидация конкретного инструмента после подстановки, обязательная типизация необработанных слотов. ВерсияDSL — явная: расширение парсера не должно внезапно включить старыеapproved, которые раньше не выполнялись. `ask_user`/picker — ожидание, не успех. Подтверждения связываются с actor/event/recipient/версией плана. Ошибки и неизвестный результат записи различаются; повтор объяснения не повторяет запись.

## Публикация и остаток

SSG в `docs/intents/`: Markdown для GitHub, HTML для статического хостинга, JSON для проверки. Один детерминированный generator, без датnow, CDN и БД; свежесть проверяет обычныйCI. Приватная статистика — отдельный датированный аудит, не публичные записи чужой переписки.

Текущий этап: восстановлены104, проинвентаризированы26 серверных SQLite-источников и мартовский локальный снимок, исправляются deterministic matcher и repoSSG. Ещё не завершены typedDSL, semantic retrieval experiment, семантическая разметка всего корпуса, индивидуальная runtime-приёмка104 и production-замена55. Остальные инциденты/deploy296/contacts255/GoogleSync223–225/routing260–267 остаются в общем плане, а не закрываются этим документом.
