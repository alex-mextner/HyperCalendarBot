# Lena incident closeout: complete invitation roster answers

Task: [roster presentation](https://github.com/alex-mextner/HyperCalendarBot/issues/581).
Parents: [incident audit](https://github.com/alex-mextner/HyperCalendarBot/issues/241), [intent recovery](https://github.com/alex-mextner/HyperCalendarBot/issues/334).

## Regression and scope
A successful deterministic roster read displayed raw user IDs and English RSVP values, then triggered an unsolicited AI question asking the requester to identify themselves.

## Implementation and acceptance
1. Reproduce the observed pipeline result using synthetic users, real SQLite, the matcher and tool handlers. Test requester identity, viewer-scoped aliases, public group labels and escaped names.
2. Resolve display labels only after access checks. Personal aliases belong to the requesting viewer and are never used in group output. Preserve numeric fallback, invitation status precedence and organizer semantics.
3. Add a runtime-only `completeResponse` signal to a successful tool answer. The executor carries it only for its direct final tool output, without preceding write evidence. Explicit workflow responses, later ordinary tools, failures, handoffs and suspensions do not inherit it.
4. The matcher sends that final answer once and does not request an AI supplement. Existing incomplete answers retain their current behavior. No seed replacement, schema migration or global supplement switch is needed.
5. Run focused RED/GREEN regressions, full native tests, TypeScript, lint and fresh-context review before normal shipping. Verify deployed revision and one read-only Telegram response; never replay historic deletion or invitation writes.

Separate work: title-based roster lookup remains [task553](https://github.com/alex-mextner/HyperCalendarBot/issues/553). Calendar read coverage and date interpretation remain in their existing PRs; this patch does not change their worktrees or tool visibility.
