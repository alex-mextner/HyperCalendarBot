# Explicit workflow input version 2

Related: #204 (typed tool inputs), #130 (whole-corpus and scenario redesign).

Version 1 / absent version retains its string-only tool-input schema. Previously invalid unversioned definitions are not enabled by widening a shared parser. Version 2 must be explicitly authored, reviewed and applied to an individual definition. There is no automatic reseed or approval change in this patch.

Version 2 accepts bounded JSON data: strings/templates, finite numbers, booleans, null, arrays and plain objects. Before recursive parsing, an iterative guard rejects cycles, accessor objects, prototype keys and excess depth/node/string budgets. Unknown versions fail rather than having their version field stripped by a legacy parser.

The resolver preserves typed literals and entire-value interpolation. An unresolved authored reference fails before dispatch; braces inside a user-supplied argument remain ordinary data. Translation cycles are bounded. Bound arguments are checked against the actual tool schema; this does not replace the tool handler's ownership and business rules.

`ask_user` returns a typed prompt and options and suspends before later steps. Resume must reference an actual question step. Replies outside the offered options do not advance. The normal chat pipeline sends reply-keyboard choices as ordinary user messages, so they return through the workflow layer rather than the separate AI-only inline-button path. Session keys remain chat+actor.

Waiting and delivery state are persisted in the existing workflow-session JSON. A second question saves its new step instead of discarding the remaining workflow. If prompt delivery fails, the next turn resends that exact stored prompt, not the previous mutations and not a fabricated successful response. Typed tool results survive the session codec; the terminal reply removes the reply keyboard.

Limits and behavior are covered by synthetic tests, including real SQLite settings and session repositories. No external account, invitation recipient, or production calendar is touched by these tests.

## Separate release obligations

This language change is not permission to activate the 98 recovered candidates. Each needs matching negatives, exact arguments, context/confirmation tests and a versioned replacement plan. Whole-conversation semantic labels, regex execution isolation, durable exactly-once mutation receipts, topic-level session scoping and historical definition migrations remain the parent redesign work.

The shipped six-seed module is unchanged. Public SSG continues to distinguish those definitions from recovered candidates and never presents candidate count as deployed coverage.

Strict resolution also has a shared operation budget (8192 nodes/references) so acyclic, repeated empty translations cannot cause exponential work. Display text is escaped before HTML chunking in both initial and resumed v2 replies; the AI supplement receives the original plain text.

Scheduled execution explicitly declares no interactive continuation. Workflows containing questions (legacy or v2) are refused before their first tool, instead of executing writes and becoming stranded without a saved question. Ordinary interactive legacy input compatibility is unchanged.
