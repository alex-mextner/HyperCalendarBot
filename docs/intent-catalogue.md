# Каталог предустановленных интентов

Источник истины: `src/services/intent/seed-catalog.ts`. Скрипт `scripts/seed-intents.ts` использует эти же данные. Импорт каталога не открывает БД. Перенос данных не меняет поведение применения сида.

| Ключ | Задача | Пример | Проверка текущего контракта |
|---|---|---|---|
| show_today | События сегодня | что у меня сегодня | Схема и свои примеры проходят ограниченную проверку |
| show_tomorrow | События завтра | что у меня завтра | То же |
| show_week | Текущая неделя | расписание на неделю | То же |
| free_slots_today | Свободные интервалы | свободные окна сегодня | То же |
| search_events_by_query | Поиск по словам | найди встречи про стендап | Exact-match теряет capture $1 |
| create_event_named_tomorrow | Создание завтра с подтверждением | создай стендап завтра в 10 | Массив ask_user.options не проходит string-only WorkflowSchema; literal examples теряют captures |

Это описание предназначения, не гарантия end-to-end успеха и не все возможности AI-инструментов. После успешного интента предусмотрен AI-supplement.

## Как получить приватную страницу

```bash
bun --no-env-file scripts/intent-catalog-report.ts \
  --db /absolute/path/to/existing/calendar.db \
  --out /private/output/intent-report --revision FULL_SOURCE_SHA
```

SQLite открывается readonly, затем PRAGMA query_only. Определения и статистика читаются в одной read transaction. `--stdout` вместо `--out` возвращает JSON, не записывая артефактов на хосте. База не создаётся при ошибке пути. Максимум 2000 определений и последние 5000 history rows; сырой текст не экспортируется. На больших базах нужен отдельный потоковый аудит, а не увеличение лимитов вслепую.

Страница полностью автономна: нет CDN, аналитики и сетевых запросов; поиск и фильтры работают локально. JSON и HTML сохраняются с правами 0600 в каталоге 0700. Не коммитить реальные снимки и не публиковать их в открытом PR. Накопленные canonical names и фразы могут содержать личные сведения: по умолчанию видны только номера записей и вызовы инструментов.

Для визуальной проверки без личных данных:

```bash
bun --no-env-file scripts/preview-intent-catalogue.ts /tmp/catalogue-demo
```

## Как интерпретировать статистику

- `intent_match` записывается до исполнения. Поля `success=1` по умолчанию недостаточно для вычисления успешности workflow. Нет исторической версии определения и явной связи с окончательным результатом: success rate остаётся `null`.
- `approved` — доступен matcher, не обязательно допустим текущему executor. Отчёт отдельно проверяет WorkflowSchema и validateWorkflow.
- Совпадение canonical_name с сидом не доказывает происхождение из seed-run. Содержимое может быть отредактировано или расширено после обучения; статус и дата создания не являются историей версий.
- Повторное сопоставление с текущим сидом использует настоящий matcher, но не исполняет инструменты. Логи `role=user` включают команды и кнопки; структурированные события исключены из текстовой выборки. Неизвестные пользовательские regex не исполняются в аудите.
- Сокращённые input_summary матчей анализируются отдельно от chat_history. Поле examined исключает слишком длинные строки; skippedOversized показывает число исключений. В replay поле window относится только к проверенным текстам, sampledWindow — ко всем выбранным строкам, включая исключённые. Их совпадения не восстанавливают исторический workflow и не доказывают полноту исходного текста.
- Окна хранения и состав журналов различаются. Нельзя делить matches на все role=user, путать multi-tool actions с пользовательским спросом или считать успешное создание приглашения его доставкой.
- Пропавшая таблица статистики даёт `null`, а не ноль; пустая существующая таблица даёт ноль с пустым временным окном.

## Безопасное применение сида — отдельная работа

Текущий `seed-intents.ts` выполняет upsert с перезаписью фраз, regex, workflow и статуса approved. Не запускайте его для построения отчёта: это может потерять обучение и вернуть отклонённое правило. Нужны versioned seed, dry-run diff, сохранение approval и отдельный migration review. Связанные задачи: #181, #204; расширенный неслитый PR #205.

Приоритетные следующие шаги: исправить потерю captures и типы DSL с TDD; версионировать определения и события исполнения; классифицировать реальные unmatched запросы на приватном корпусе; только затем поэтапно принимать расширенный сид. Положительная ретроспективная маршрутизация — не разрешение автоматически применять write-intents.
