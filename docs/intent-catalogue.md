# Каталог интентов: где что лежит

Единый рабочий набор правил описан в исходниках: `src/services/intent/seed-catalog.ts` и модули `seed-*.ts` рядом с ним. Импорт каталога не открывает базу данных.

| Что нужно | Куда смотреть |
|---|---|
| Все правила, их шаги, привязки и происхождение от прежних правил | [Каталог для GitHub](intents/README.md) |
| Та же информация с поиском и фильтрами (одна страница без сети) | [`intents/index.html`](intents/index.html) |
| Как устроен движок: типизированные привязки, вопросы, подтверждение, доказательство записи, права | [Описание движка](intents/engine.md) |
| Машиночитаемый каталог с отпечатком целевого сида | [`intents/catalogue.json`](intents/catalogue.json) |
| План и история перестройки | [План](plans/2026-09-18-intent-redesign.md) |

Каталог и HTML-страница описывают **целевой сид из исходников**. Они не утверждают, что сид установлен в какой-либо базе: это подтверждается отдельно сравнением отпечатка с записью `intent_basis_manifest` в живой базе.

## Как создать и пересобрать документацию

```bash
bun run docs:intents          # пересобрать README.md, index.html и catalogue.json
bun run docs:intents:check    # завершится ошибкой, если файлы отстали от исходников
bun --no-env-file scripts/verify-intent-docs.ts   # проверить настоящую страницу в Chromium
```

Русские заголовки правил лежат в [`scripts/intent-doc-labels.ts`](../scripts/intent-doc-labels.ts); без заголовка нового правила сборка падает. Обычный тестовый прогон проверяет свежесть файлов и то, что все относительные ссылки указывают на существующие файлы.

## Безопасное применение сида к базе

Правка исходников базу не меняет. Замена набора интентов делается скриптом [`scripts/replace-intent-basis.ts`](../scripts/replace-intent-basis.ts): сначала пробный запуск (база открывается только на чтение), затем применение с отпечатком из пробного запуска и **новым** путём резервной копии. Команды и проверки описаны в [движке](intents/engine.md#безопасная-миграция-базы-сначала-пробный-запуск). Старый `scripts/seed-intents.ts` теперь вызывает тот же скрипт и не делает молчаливый upsert.

## Приватный отчёт по живой базе

```bash
bun --no-env-file scripts/intent-catalog-report.ts \
  --db /absolute/path/to/existing/calendar.db \
  --out /private/output/intent-report --revision FULL_SOURCE_SHA
```

SQLite открывается только на чтение. `--stdout` вместо `--out` возвращает JSON, не записывая файлов на хосте. Сырой текст сообщений не экспортируется. Отчёт содержит данные пользователей: не коммитьте его и не публикуйте в открытом PR. Для проверки внешнего вида без личных данных: `bun --no-env-file scripts/preview-intent-catalogue.ts /tmp/catalogue-demo` (см. [`scripts/preview-intent-catalogue.ts`](../scripts/preview-intent-catalogue.ts)).

Как читать статистику: запись `intent_match` создаётся до исполнения и не доказывает успех workflow; отсутствие таблицы статистики даёт `null`, а не ноль; повторное сопоставление истории с текущим сидом использует настоящий сопоставитель, но не исполняет инструменты и не восстанавливает исторические определения.
